# Embedded Course - Template Repository

Цей репозиторій є шаблоном для виконання домашніх завдань на курсі Embedded.
Він налаштований для роботи з мікроконтролерами **ESP32S3** та **STM32F411 (BlackPill)**.

## 🚀 Як почати роботу

1. **Зробіть форк (Fork)** цього репозиторію до свого облікового запису на GitHub.
2. **Обов'язково перейменуйте свій форк** у налаштуваннях репозиторію (Settings -> General -> Repository name). Нова назва має бути у форматі EMB_21_Ім'яІніціал (наприклад, `EMB_21_JohnD`).
3. Склонуйте ваш перейменований форк на свій комп'ютер:
   ```bash
   git clone <URL_вашого_форку>
   cd <назва_вашого_репозиторію>
   ```
3. Для кожного нового домашнього завдання **створюйте окрему гілку** від `main`. Назва гілки має **обов'язково співпадати** з назвою директорії домашньої роботи:
   - Для звичайного ДЗ: гілка `hw_1.1` і папка `hw_1.1`.
   ```bash
   git checkout -b hw_1.1
   ```
   - Для мініпроєкту: гілка `hw_miniproject_1` і папка `hw_miniproject_1`.
   ```bash
   git checkout -b hw_miniproject_1
   ```
4. Створіть папку для домашнього завдання з **такою ж назвою**, як і гілка.
5. Пишіть код! Ви можете використовувати PlatformIO. В корені лежить базовий `platformio.ini`, який можна копіювати у папку завдання, або налаштувати свій.
6. Коли завдання виконано, зробіть коміт, запуште гілку та відкрийте **Pull Request (PR)** у `main`.

## ⚙️ CI/CD та Автоматизація

Цей репозиторій має вбудовані перевірки GitHub Actions, які **обов'язково мають бути успішними (зеленими) для того, щоб ваш Pull Request був перевірений та прийнятий**:
- **Перевірка форматування коду**: Ваш код повинен відповідати правилам `.clang-format`. Щоб не було проблем, налаштуйте автоматичне форматування в вашому редакторі/IDE (VSCode, CLion).
- **Збірка (Build)**: Система неперервної інтеграції (CI) автоматично визначає, який інструмент ви використовуєте, базуючись на файлах у вашій папці з домашнім завданням:
  - **PlatformIO** (якщо є `platformio.ini`): Код компілюється під ті платформи, які вказані у вашому `default_envs`.
  - **ESP-IDF** (якщо є `CMakeLists.txt`, а `platformio.ini` відсутній): Код компілюється офіційним інструментарієм ESP-IDF (ціль за замовчуванням: `esp32s3`).
  - **STM32 CubeMX / Нативний Makefile** (якщо є `Makefile`, а інші файли відсутні): Код компілюється за допомогою `arm-none-eabi-gcc` та `make`.
  - **Увага щодо попереджень (Warnings):** У проєкті (зокрема для PlatformIO) налаштовано сувору перевірку вашого коду (через `-Werror`), що означає, що **будь-який warning у вашому коді розцінюється як помилка** і призведе до падіння пайплайну. 
  - **Попередження в бібліотеках (PlatformIO):** Ми вже налаштували середовище таким чином, що суворі прапорці перевірки (`build_src_flags` у `platformio.ini`) застосовуються лише до вашого сирцевого коду, тому попередження у зовнішніх бібліотеках не блокуватимуть збірку. Якщо ж вам потрібно локально приглушити якийсь специфічний warning у власному коді, використовуйте директиви `#pragma` (наприклад, `#pragma GCC diagnostic ignored "-W..."`), але **обов'язково додавайте коментар з поясненням**, чому це необхідно і безпечно.

## ❓ FAQ

### Як встановити PlatformIO?
1. Встановіть [VSCode](https://code.visualstudio.com/).
2. Додайте розширення **PlatformIO**.
3. Відкрийте проєкт і переконайтесь, що все встановлено правильно.

### Як налаштувати IDE для роботи з проєктом?
1. Встановіть розширення **Clang-Format** у VSCode.
2. Додайте налаштування у `.vscode/settings.json`:
   ```json
   {
       "editor.defaultFormatter": "xaver.clang-format",
       "editor.formatOnSave": true,
       "[c]": {
           "editor.defaultFormatter": "xaver.clang-format"
       },
       "[cpp]": {
           "editor.defaultFormatter": "xaver.clang-format"
       }
   }
   ```

### Як вирішити проблеми з компіляцією?
- Переконайтесь, що ви використовуєте правильну версію PlatformIO.
- Виконайте команду `platformio update` для оновлення інструментів.
- Перевірте прапорці компіляції у `platformio.ini`.

```c
#include <Arduino.h>

#define LED_PIN  13
#define DELAY_MS 1000

void setup() {
    pinMode(LED_PIN, OUTPUT);
}

void loop() {
    digitalWrite(LED_PIN, HIGH);
    delay(DELAY_MS);
    digitalWrite(LED_PIN, LOW);
    delay(DELAY_MS);
}
